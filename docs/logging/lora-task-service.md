# lora-task-service — logging fixes

**Squad:** LORA Core
**Production service:** `prod-lora-task`
**Stack:** Go, zerolog

3.82 million warnings over seven days. This is the highest warning volume in production and
almost none of it describes a problem.

---

## 1. Routine conditions logged as warnings

Measured over six hours:

| Pattern | Count |
|---|---:|
| Generic `<msg> <path>` pattern | 3,371 |
| `missing in form submission?` | 1,067 |
| `msgDispatch - got sign channel is closed` | 131 |
| `unexpected client close` | 130 |
| `field layout does not have a valid data reference, skipping` | 97 |
| `Auth cookie not found, redirect to OIDC SSO provider` | 55 |
| `queue is currently closed` | 35 |

Six of these seven are normal operation:

- **`missing in form submission?`** —
  `internal/httpserver/handlers/frontend/task/action.go:306`. An optional form field being
  absent is expected. The trailing question mark suggests the author was unsure too.
- **`unexpected client close`** — a browser tab closing during a websocket session.
- **`Auth cookie not found, redirect to OIDC SSO provider`** — that is the login flow
  working.
- **`queue is currently closed`** and **`got sign channel is closed`** — shutdown paths.

### Fix

Move all of these to `log.Debug()`:

```go
log.Debug().Str("field", field).Msg("optional field absent in form submission")
```

Keep `warn` for things an operator should act on. If the answer to "would anyone do
something about this?" is no, it is not a warning.

`field layout does not have a valid data reference, skipping` is the one worth keeping at
warn — a layout referencing missing data is probably a configuration error someone should
fix. 97 in six hours suggests it is a real and recurring one.

## 2. 106 `console.log` — mostly generated, mostly harmless

| File | Count | Note |
|---|---:|---|
| `static/partnership-ndf-queue-guest/partnership-ndf-queue-guest-*.js` | 20 | Compiled browser bundle — runs in the browser, costs nothing |
| `internal/render/templates/partnership/asset_price_availability_dropdown_templ.go` | 15 | Generated by `templ`, emitted into browser JavaScript |

Neither reaches Cloud Logging. The generated `_templ.go` files should not be edited by hand
— change the `.templ` source if the browser-side logging matters for data exposure.

No action needed for cost.

## 3. 32 exception logs and 11 body logs

| File | Item | Count |
|---|---|---:|
| `internal/service/arango/store.go` | error logs | 5 |
| `internal/httpserver/handlers/backend/task/update.go` | error logs | 4 |
| `internal/httpserver/handlers/frontend/rtc/queue_server.go` | body logs | 4 |
| `internal/httpserver/handlers/frontend/proxy/invoke.go` | body logs | 2 |

`proxy/invoke.go` is worth a look — a proxy handler that logs bodies logs whatever passes
through it. Log the target, status and duration instead.
